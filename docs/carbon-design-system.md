# Using IBM Carbon in Code60

Start with the task the person is trying to complete. For example, opening a project calls for a choice among recent projects and a way to browse folders. That decision determines what belongs in the body, which action belongs in the footer, and where focus should return. Use Carbon to make those decisions as well as to implement the controls.

## Design a change

1. **Place the action.** Put an application-wide action in the shell, a collection action in its toolbar, and a row action beside the object it affects. Give the page a task-oriented heading. Name each action for its effect, especially where a choice is irreversible. [Migration examples by task](carbon-migration.md#guidance-and-implementation)
2. **Consult IBM’s Carbon MCP server.** Use `docs_search` for pattern selection, layout, content, interaction, and accessibility. Then use `code_search` for the React composition. Read the linked IBM section and compare the example with the installed package and Code60’s shared adapters. If the server is unavailable, go directly to the IBM guidance and inspect the installed source. [IBM’s Carbon MCP setup guide](https://www.carbondesignsystem.com/getting-started/carbon-mcp/onboarding-and-setup) · [Renderer conventions](../src/renderer/AGENTS.md#carbon-implementation-boundaries)
3. **Compose the whole interaction.** Use the product grid, spacing tokens, productive type, and semantic theme tokens to establish hierarchy. Decide what happens on empty, busy, failed, and successful states. Identify the first keyboard target, the accessible name of each control, and who owns focus and unsaved work when the user leaves. [2x Grid](https://carbondesignsystem.com/building-blocks/foundations/2x-grid/guidelines/) · [Themes](https://www.carbondesignsystem.com/building-blocks/foundations/themes/overview)
4. **Verify the task in the renderer.** Exercise the visible controls by pointer and keyboard. Check both completion and cancellation, a narrow or short viewport, light and dark themes, and forced colors where appearance changes. For animation, also check reduced motion. Capture evidence for the behavior the PR changes. [Workflow QA](../.factory/skills/qa/SKILL.md) · [Checked-in visual reviews](review/carbon-full-app/README.md)

## Exception register

Update this register **in the same PR** that introduces, changes, or retires a departure. Give each entry a surface, the usual Carbon treatment, the local choice and its reason, the boundary where it applies, and a link to tracked implementation, tests, or a merged decision. For a workaround, include what would allow its removal. If you find an unexplained discrepancy, describe it as an open question in the PR until its purpose can be verified. When retiring an entry, identify its replacement so the old treatment does not spread.

### Compatibility workaround

**Carbon React 1.121 modal focus.** The usual composed modal owns focus handling. In this version, blur-driven centering can move a footer control between pointer-down and click, losing the action on a short screen. The shared wrapper stops blur propagation at its header, body, and footer after child handlers run. Keep the adjustment there. On a Carbon upgrade, test a bottom action by pointer in an overflowing dialog, then check field validation, Tab, Escape, and nested-chooser focus restoration with the guard removed. Retire the guard when those interactions pass with native focus handling alone. [Wrapper and rationale](../src/renderer/modal.tsx) · [Chooser journeys](../test/browser-features.e2e.ts)

### Supported configuration and historical decisions

Carbon AI Chat supports an embedded frame and optional history. Code60 configures the frame, launcher, and Carbon history off. The selected Code60 thread still displays its existing messages. The authenticated backend owns messages, runs, and approvals. Treat this as a supported integration choice when consulting the register. [Chat configuration](../src/renderer/carbon-conversation.tsx) · [Transcript reconciliation](../src/renderer/carbon-transcript.ts)

The old white-on-blue Light header had an explicit contrast exception. That palette and its waiver are **superseded**. Use the current White/G100 theme roles and verify text, selection, and keyboard focus in the shipped header. Older screenshots and historical styling notes describe earlier releases. [Current architecture](../ARCHITECTURE.md#carbon-application-presentation) · [Renderer migration direction](../src/renderer/AGENTS.md)

## Lessons from the migration

| Symptom | Cause | Practice | Verify |
| --- | --- | --- | --- |
| A chooser looks stretched or its last action disappears. | Fixed sizing or a scrolling outer container puts the footer in competition with a long list. | Choose the dialog type for the task, size it to content within the viewport, and scroll the body. | Try empty and long recent-project lists, open the nested folder chooser, and click the last footer action on a short screen. [Open Project browser journey](../test/browser-features.e2e.ts) |
| A destructive decision is hard to distinguish or too easy to accept. | Generic button text hides the consequence and initial focus can make Enter activate the destructive action. | Use an explicit verb such as **Discard worktree**, style the action as danger, and initially focus **Cancel**. | Test Tab, Enter, Escape, and return focus. In an isolated fixture, exercise cancel and confirm and check the underlying outcome. [Confirmation actions and danger styles](../src/bridge/gateway.ts) · [Shared modal](../src/renderer/modal.tsx) |
| React reports a list item inside another list item. | A navigation component emits its own list item inside a hand-written destination wrapper. | Inspect the DOM Carbon renders. Give each item a parent list and preserve the disclosure button’s keyboard behavior. | Inspect the open section’s DOM and console, then navigate by keyboard and close a nested dialog with Escape. [Navigation composition](../src/renderer/page-tabs.tsx) · [Disclosure tests](../src/renderer/sidebar-disclosures.test.tsx) |
| Content edges drift, or an accent works in one theme only. | Padding adds to column gutters, and literal colors bypass theme roles. | Give the grid ownership of the outer inset and map the accent through semantic tokens. | Measure both edges at 42rem and on either side of it. Inspect text, focus, selection, and status in White, G100, and forced colors. [Grid rules](../src/renderer/carbon/application.scss) · [Appearance tests](../src/renderer/appearance.test.ts) |
| Switching chats or reconnecting risks a duplicate reply or a misplaced draft. | Carbon’s visible transcript and the authenticated Code60 thread have different lifetimes. | Reconcile by stable message and conversation identity. Route Send, Stop, and approval to the owning Code60 conversation. | Switch between two streaming chats, reload mid-turn, and return to each draft. Confirm the reply appears once and approval still requires a decision. [Transcript tests](../src/renderer/carbon-transcript.test.ts) · [Concurrent chat and reconnect journeys](../test/browser-features.e2e.ts) |
