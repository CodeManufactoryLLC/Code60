# Renderer

- Orchestrator and worker chats use borderless agent text and solid user bubbles: verdigris in Light, gold in Dark/System dark, with contrasting text. Activity/tool disclosures remain distinct. Copy uses a 12px Carbon icon without a fill or border, outside user bubbles, with glyph highlighting on keyboard focus and a 24px hit target. Keep a single resizable file panel after the conversation, stacking below Chat at 1200px and below. Give it the left navigation fill throughout, including Monaco, and a Carbon drawer toggle inside its tab header. Minimize to a visible 48px rail (a compact header below Chat on narrow windows); animate expansion/minimization with reduced-motion support. Keep the resize grip borderless at rest, with visible keyboard focus.
- Conversation rows show the Carbon chat icon and numeric badge only for unread replies, independently of activity/errors. Count each turn once at its first nonempty agent text. Opening Chat marks all present replies read regardless of scroll; open-chat streams stay read. Persist only database/run-scoped read markers in session storage, never message content; use pushed events without polling or new IPC.

`src/renderer` is the React interface, built by Vite into `dist/renderer`.

- Reach the main process only through `window.desktop`. Import only types from `core`, and nothing from Node.js or Electron.
- Render agent output, prompts, and diffs as text. Never use `dangerouslySetInnerHTML` or load remote content; the Content Security Policy forbids it.
- Merge updates by revision with `applyUpdate`, so reloads and startup never lose or duplicate events.
- Show status as text, not only as color. Keep controls labelled, keyboard reachable, and their shortcuts visible.
- Support Light, Dark, and System appearance, and the opt-in Signal colors (`data-signals`), with the CSS variables in `style.css`. Light uses white surfaces with subtle borders and restrained shadows to distinguish them, with teal actions (`#43b3ae`) and pale viridian hover fills; selection uses neutral gray; saved Paper selections migrate to Light. Dark and System dark use dark steel-gray (`#242b33`) wherever Light uses white for neutral resting surfaces, with white text, `#aaaaaa` muted text, `#414b56` subtle borders, `#888888` control borders, and `#323c46` selected fills. Preserve gold actions, green hover, colored messages, focus colors, and opt-in signals; separate fields and controls with fine borders and keep disabled stripes transparent. The Code60 wordmark’s colored 60 block has a small upper-right, 45-degree chamfer. The main Chat composer has a 24px upper-right bevel, a visible 1px border, no resting/focused shadows and focus that replaces the normal border color without a separate inset outline, including system colors in forced colors. It shares a light-gray (`#f3f3f3`) or slightly lighter steel-gray (`#2c353f`) fill with the navigation sidebar. Buttons have 5px corners; button groups round only their outer ends.
- Give every independent icon action the shared `icon-button` class: no border, shadow or background fill in resting, hovered, pressed or disabled states; hover and focus highlight only the glyph, with no focus outline even when Focus highlight border is enabled. Preserve hit targets, accessible labels, disabled semantics and visible keyboard focus. Decorative icons in labeled buttons, navigation, rows and menus inherit their parent state, never their own hover. Close, add and drag actions remain separate controls even when visually inside a tab or row.
- Use the 16px Carbon icons from `icons.tsx` (`Icon` in the DOM, `drawIcon` on canvas), except compact 12px message Copy icons, instead of text glyphs such as ×, ↑, or ▾. Write run states with `statusSpec` labels and icons; nothing blinks.
- Apply the six text roles (table headings, buttons, agent messages, human messages, page titles, and normal text) through their CSS properties and the canvas table theme. All roles default to D-DIN Regular (400) in sentence case. Use regular weight for navigation, headings, status labels, controls and the wordmark; avoid hard-coded bold or selected-state weight changes. Apply the typography defaults once to existing installations while preserving size, case and other appearance preferences. Keep code and diffs monospace and case-preserving. Bundle fonts locally and retain their licenses; keep `font-src 'self'`.
- Get external data from snapshots and request reads with `poll`; do not start timers that fetch data. Use `useTicker` from `ticker.ts` for clock-only redraws, inside the smallest component that needs it, and report visibility with `setVisibility`.
- Keep Glide Data Grid imports in the renderer. Import its bundled CSS and pass theme colors resolved from the app's CSS variables, since the grid draws on a canvas; do not inject styles or weaken the Content Security Policy. Preserve row selection by session ID across sorting and data updates, and support clicking a row or pressing Enter on a cell to open its chat. The Actions cell opens its session's actions menu instead; keep that menu keyboard reachable.
- Build tables with `DataTable` from `data-table.tsx`, so every table shares Glide's search, header-menu filters, add row, and per-table settings. Save table preferences by stable column ID through `useTableView`; keep ad hoc column filters in memory. Named definitions and one active selection persist by table and database/project with `saved-filters.ts`; incompatible definitions must remain visible and unapplied. Use explicit column filter types so empty tables do not change their meaning.

- Give standalone buttons a 5px radius without a trailing-edge border effect. In button groups, round only the first control’s left corners and the last visible control’s right corners, with straight separators between controls. Main page surfaces have no outer border and retain 5px corners. Hover changes the fill without introducing a border. Inputs, checkboxes, radios, switches, scrollbar thumbs, dialog panels and overlays stay square; the logo and main Chat composer have upper-right chamfers. Standard button groups use 28px controls (30px overall), with 24px controls for compact groups. Table headers put the page title on the left and the control group on the right, wrapping on narrow screens. Button groups have no overlap or cutouts; give them a fine outer border, a restrained shadow, and white fills in Light and steel-gray fills in Dark. Use the standard Carbon checkmark. Focus outlines and glows follow the Focus highlight border preference, which defaults off, except independent icon actions use glyph highlighting without an outline; preserve keyboard focus behavior, validation baselines, filled resting controls and restrained overlay shadows.
- Table Settings opens a native modal with draft controls and a four-row fictional Glide preview. Reuse shared canvas styling and width calculations. Apply commits once; Cancel, Escape and close discard drafts. Reset is draft-only and removes the saved override when applied without further edits. Keep at least one data column visible, including when chart columns are turned off. Restore trigger focus, keep the header/footer visible, use two-column display toggles without row dividers, and discard drafts on workspace replacement. Put column visibility toggles in a closed-by-default dropdown above the orange dotted preview frame; Escape dismisses that dropdown before the modal. Scrollbars should remain subtle in both themes, with stronger hover contrast and system colors in forced-color mode.

- Default canvas gridlines off; preserve per-table line settings. Use white headers and rows in Light, steel-gray headers and rows in Dark, and resolved CSS colors in Glide. Preserve explicit labels when colors change or forced colors apply.
- Search and Messages use `useTranscripts` and its project-scoped cache. Bound concurrent history reads, deduplicate requests, expose partial failures/retry and discard stale project responses. Search may request the dedicated evidence-only summary helper through its validated bridge; do not expose generic agent execution or telemetry capabilities.

- Use one application footer across the full window bottom, with a clear top border. Keep polling, updates and an actionable pending-approval count here, never chat heads or popups. Keep page panels free of internal footer space and treat the footer as opaque during transparent-window hit testing.

- Keep the selected conversation's agent-message age above the footer’s top border. Dark footer surfaces are steel-gray.

- Enclose repository identity and page navigation in one square-edged sidebar with a subtle 1px theme-aware border and 6px content padding. Align its top and bottom with the desktop right file panel, leaving the shared 12px bottom inset above the footer. Keep the native-control drag strip separate, without extending the sidebar fill into it. Its Carbon drawer toggle mirrors the file panel control, collapses to a 48px rail, and animates the workspace columns over 200ms with reduced-motion support. Keep matching 12px left and right workspace insets. Start expanded and preserve navigation, conversations, drafts and disclosure state while collapsed. The rail keeps accessible icon-only top-level navigation; hide the project card, nested groups, New chat action and version footer. Hover temporarily expands an unpinned sidebar until the pointer leaves; the drawer toggle pins it open. Activating a collapsed disclosure or pressing Right expands and pins it for keyboard access. Its labeled buttons and the project card match the sidebar fill, including selected and disabled controls; only enabled hover uses viridian. Selection keeps contrasting text and accessible state without a separate fill. The tab list scrolls within the available height. Its filled interior, including gaps between buttons, stays opaque to transparent-window hit testing.

- Give every page-navigation item a locally bundled 16px Carbon icon to the left of its label, with 8px spacing. Icons inherit the tab’s state color and remain decorative to assistive technology; labels and alphabetical keyboard order remain authoritative.

- Settings exposes the shared agent setup wizard through Add agents and Change primary, plus the fixed allow-all switch. Present bundled logos and alphabetical Antigravity, Claude, Codex, Copilot, Droid, Kiro and OpenCode choices as agent cards that immediately start detection and connection on click or Enter/Space, never radio inputs or a separate Continue step. Use compact wizard typography (16px headings, 13px body and controls), independent of larger page-title settings. Keep arrow/Home/End focus navigation and Enter/Space selection. Select primary first, detect and connect automatically, then ask whether to add another agent. Show only Detected and Connected as agent statuses; use separate progress and error messages with retry/cancel controls. Preserve native keyboard navigation, live progress announcements, D-DIN and theme tokens, and reduced-motion support. Persist no verification in renderer storage.

- Require completed main-process setup before splash entry, including renderer reloads and existing installations. Dismissing setup leaves entry blocked. Render the recoverable main-process session and commit only through Finish setup. Membership is configured, not a permanently live connection. Preserve the Start/recent-project Yes/No flow after completion.

- Put an icon-only, labelled Carbon plus action immediately left of the Chat disclosure chevron, as a separate button, never nested in the tab. Keep it reachable when the Chat group is collapsed in the expanded sidebar; hide it in the compact rail. Creation reveals the group. Nest only labelled conversations beneath Chat. Use 4px vertical navigation padding and 28px minimum rows, growing with typography. Share in-flight guards and visible errors between creation and conversation selection. Remember expansion; reveal externally selected conversations. Collapse never changes the conversation. Preserve independent drafts, transcripts and scroll positions; activity and failure indicators remain visible on background conversations. No secondary sidebar or standalone Files page.

- Present orchestration Chat as a conversation: right-aligned user messages, borderless assistant replies without repeated speaker labels, expandable Activity for thoughts/tools/permissions, and a persistent composer. Show a larger Code60 wordmark above New conversation only in the empty conversation view; keep the current provider directly below the main composer. Keep progress visible with explicit text and a reduced-motion-aware 12px striped loading line inside the composer’s top border, with a matching 6px line inside the top edge of each connecting, working or stopping conversation entry in the primary sidebar; replace Send with Stop during a turn. Errors stay outside collapsed activity.

- Display automatic worker prompts as labelled activity, never as user messages. Show paused worker updates with a keyboard-reachable Resume updates control bound to the current chat ID. Label orchestrator-owned worker chats as allowing all actions. MCP contract descriptions must distinguish read-only tools from tools that change worker state.

- Group Configurations, Messages, Polling, Sessions and Worktrees beneath the expandable Tables sidebar item. Use the Carbon grid icon for Tables and every table child. Keep top-level pages and table children alphabetized. - Files uses Headless Tree and the shared read-only Monaco inspector. Keep filesystem access scoped through `setFileContext` and refreshed by the main-process Files poll source. Keep renderer-only blank, Explorer and file tabs separate from page navigation; clear them on project/database changes and reloads. Hide the panel outside Chat while preserving tabs, order, drafts and editor scroll/selection state in memory. Request filesystem context and polling visibility only for the selected Explorer/file tab while the panel is visible; discard stale reads.

- Files uses borderless page and inspector surfaces with `--chat-neutral` fill, neutral selection and viridian hover.
