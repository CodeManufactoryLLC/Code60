# Renderer

- Orchestrator and worker chats use borderless agent text and solid user bubbles: verdigris in Light, lighter verdigris in Dark/System dark, with contrasting text. Activity/tool disclosures remain distinct. Copy uses a 12px Carbon icon without a fill or border, outside user bubbles, with glyph highlighting on keyboard focus and a 24px hit target. Keep a single resizable file panel after the conversation, stacking below Chat at 1200px and below. Give it only a left divider and the left navigation fill throughout, including Monaco, and a Carbon drawer toggle inside its tab header. Close to zero width with no divider or rail, and zero height on narrow layouts. Show the reopening icon at the chat area's top right when closed, reserving header space so actions do not overlap it. Keep hidden contents inert; preserve toggle focus, tabs, preview state and expanded width. Animate expansion/closing with reduced-motion support. Keep the resize grip borderless at rest, with visible keyboard focus.
- Conversation rows show the Carbon chat icon and numeric badge only for unread replies, independently of activity/errors. Keep counts and status icons in a separate reserved column; ellipsize names before they overlap those indicators. Count each turn once at its first nonempty agent text. Opening Chat marks all present replies read regardless of scroll; open-chat streams stay read. Persist only database/run-scoped read markers in session storage, never message content; use pushed events without polling or new IPC.

`src/renderer` is the React interface, built by Vite into `dist/renderer`.

- Reach the main process only through `window.desktop`. Import only types from `core`, and nothing from Node.js or Electron.
- Render prompts, activity, tool output, and diffs as text. Agent replies in both chats alone may use ChatMarkdown (react-markdown and remark-gfm) to render safe React elements, including semantic emphasis. Never use `dangerouslySetInnerHTML`, raw-HTML plugins, or remote images/embeds. Links allow only validated HTTP(S) destinations through openWebLink and native confirmation; never navigate Electron. Copy retains exact source. Preserve the CSP.
- Merge updates by revision with `applyUpdate`, so reloads and startup never lose or duplicate events.
- Show status as text, not only as color. Keep controls labelled, keyboard reachable, and their shortcuts visible.
- Support Light, Dark, and System appearance, and the opt-in Signal colors (`data-signals`), with the CSS variables in `style.css`. Light uses white surfaces with subtle borders and restrained shadows to distinguish them, with teal actions (`#43b3ae`) and pale viridian hover fills; selection uses neutral gray; saved Paper selections migrate to Light. Dark and System dark use jet black (`#000000`) wherever Light uses white for neutral resting surfaces, with white text, `#aaaaaa` muted text, `#444444` subtle borders, `#888888` control borders, and `#303030` selected fills. Use lighter verdigris actions and user bubbles (`#77ccc8`), related focus and hover colors, and opt-in signals; separate fields and controls with fine borders and keep disabled stripes transparent. The Code60 wordmark’s colored 60 block has a small upper-right, 45-degree chamfer. The main Chat composer has square corners, a visible 1px border, no resting/focused shadows and focus that replaces the normal border color without a separate inset outline, including system colors in forced colors. The composer and both sidebars blend into the main app surface: white in Light and steel-gray (`#242b33`) in Dark/System dark, including file previews and resting controls. All UI elements, including controls, panels, messages, and third-party overlays, use zero border radius.
- Give every independent icon action the shared `icon-button` class: no border, shadow or background fill in resting, hovered, pressed or disabled states; hover and focus highlight only the glyph, with no focus outline even when Focus highlight border is enabled. Preserve hit targets, accessible labels, disabled semantics and visible keyboard focus. Decorative icons in labeled buttons, navigation, rows and menus inherit their parent state, never their own hover. Close, add and drag actions remain separate controls even when visually inside a tab or row.
- Use the 16px Carbon icons from `icons.tsx` (`Icon` in the DOM, `drawIcon` on canvas), except 1em conversation role icons, compact 12px message Copy icons and 8px static activity fallbacks, instead of text glyphs such as ×, ↑, or ▾. Write run states with `statusSpec` labels and icons; nothing blinks.
- Apply the six text roles (table headings, buttons, agent messages, human messages, page titles, and normal text) through their CSS properties and the canvas table theme. All roles default to D-DIN Regular (400) in sentence case. Use regular weight for navigation, headings, other status labels, controls and the wordmark; avoid hard-coded bold or selected-state weight changes. Apply the typography defaults once to existing installations while preserving size, case and other appearance preferences. Keep code and diffs monospace and case-preserving. Bundle fonts locally and retain their licenses; keep `font-src 'self'`.
- Get external data from snapshots and request reads with `poll`; do not start timers that fetch data. Use `useTicker` from `ticker.ts` for clock-only redraws, inside the smallest component that needs it, and report visibility with `setVisibility`.
- Keep Glide Data Grid imports in the renderer. Import its bundled CSS and pass theme colors resolved from the app's CSS variables, since the grid draws on a canvas; do not inject styles or weaken the Content Security Policy. Preserve row selection by session ID across sorting and data updates, and support clicking a row or pressing Enter on a cell to open its chat. The Actions cell opens its session's actions menu instead; keep that menu keyboard reachable.
- Build tables with `DataTable` from `data-table.tsx`, so every table shares Glide's search, header-menu filters, add row, and per-table settings. Save table preferences by stable column ID through `useTableView`; keep ad hoc column filters in memory. Named definitions and one active selection persist by table and database/project with `saved-filters.ts`; incompatible definitions must remain visible and unapplied. Use explicit column filter types so empty tables do not change their meaning.

- Give all controls and surfaces square corners without a trailing-edge border effect. Button groups use straight edges and internal separators. Main page surfaces have no outer border. Hover changes the fill without introducing a border. Inputs, checkboxes, radios, switches, scrollbar thumbs, dialog panels and overlays stay square; the Code60 wordmark retains its branded upper-right chamfer. Standard button groups use 28px controls (30px overall), with 24px controls for compact groups. Give page headers a small bottom margin. Button groups have no overlap or cutouts; give them a fine outer border, a restrained shadow, and white fills in Light and black fills in Dark. Use the standard Carbon checkmark. Focus outlines and glows follow the Focus highlight border preference, which defaults off, except independent icon actions use glyph highlighting without an outline; preserve keyboard focus behavior, validation baselines, filled resting controls and restrained overlay shadows.
